# PRD: Visualize PRD.json on Kanban Board

## Overview
Integrate `prd.json` data into the Kanban board to visualize the progress of a session. The application will read tasks from the local `prd.json` file, map their statuses to Kanban columns, and update the UI in real-time when the file changes on the filesystem. This is a read-only visualization; changes in the UI will not write back to the file.

## Goals
- Visualise tasks from `prd.json` on the Kanban board
- Automatically map task statuses (e.g., "todo", "in_progress", "done") to appropriate Kanban columns
- Reflect external changes to `prd.json` immediately on the board (Real-time one-way sync)
- Maintain a strictly read-only view of the data source

## User Stories

### US-001: Load and Parse PRD.json
As a user, I want the application to load tasks from the `prd.json` file on startup so that I can see the current session's work items.

**Acceptance Criteria:**
- [ ] Application reads `prd.json` from the filesystem root or configured path
- [ ] JSON content is parsed into a strictly typed interface/model
- [ ] Handle missing or malformed `prd.json` gracefully (show error or empty state)
- [ ] Display the count of loaded tasks in the UI

### US-002: Map Statuses to Kanban Columns
As a user, I want tasks to appear in the correct columns based on their status so that I can understand the progress.

**Acceptance Criteria:**
- [ ] Map "todo" status to "To Do" column
- [ ] Map "in_progress" status to "In Progress" column
- [ ] Map "done" status to "Done" column
- [ ] Map unknown/other statuses to a default "Backlog" or "To Do" column
- [ ] Render basic card information (Title, ID) in the column

### US-003: Real-time File Watcher
As a user, I want the board to update automatically when I modify `prd.json` externally so that I don't have to manually refresh.

**Acceptance Criteria:**
- [ ] Implement a file watcher (e.g., `chokidar` or Node `fs.watch`) on `prd.json`
- [ ] Trigger a data reload immediately upon file change detection
- [ ] Update the UI state without a full page reload
- [ ] Debounce rapid updates to prevent UI flickering

### US-004: Read-only UI Enforcement
As a user, I want to be prevented from moving cards or editing them on the board so that I don't mistakenly think I'm updating the source file.

**Acceptance Criteria:**
- [ ] Disable drag-and-drop functionality for these specific cards
- [ ] Hide or disable "Add Item" buttons for the mapped columns
- [ ] Visual indication (e.g., lock icon or badge) that these items are managed externally via `prd.json`

## Functional Requirements
- FR-1: The system must read the standard `prd.json` schema generated by Ralph tools.
- FR-2: The system must support at least three standard status mappings: Todo, In Progress, Done.
- FR-3: The system must handle file system read errors (e.g., permissions) by logging an error and notifying the user.
- FR-4: The file watcher must be active as long as the application is running.

## Non-Goals
- Writing changes back to `prd.json` (bi-directional sync).
- Editing task details (title, description) from the UI.
- Creating new tasks in `prd.json` from the UI.
- Complex mapping configuration UI (hardcoded standard mapping is sufficient for v1).

## Technical Considerations
- Ensure the file watcher handles OS-specific file system events correctly.
- Use a robust state management solution to handle external updates flowing into the UI components.
- The `prd.json` path should be relative to the project root.

## Success Metrics
- Tasks from `prd.json` are visible on the board within 2 seconds of app launch.
- External edits to the file reflect on the UI within 1 second.
- No write operations are attempted on the source file.

## Open Questions
- Do we need to support custom columns defined in the JSON, or just map tasks to existing board columns?
- How should we handle tasks that are deleted from the JSON file while the board is open? (Assumption: Remove them from UI).
